# `typix agents-md`

Generate (or update) an `AGENTS.md` file at your project root containing Typix-specific guidance for AI coding assistants (Claude Code, Cursor, Continue, Aider, GitHub Copilot Chat, etc.).

```
typix agents-md [options]
```

## Synopsis

`AGENTS.md` is a community convention for project-level instructions read by AI coding tools. By placing one in your project root, you give every AI assistant working in your codebase the same baseline knowledge about:

- Which Typix packages are installed and their roles
- The canonical authoring patterns (`useTypixEditor`, `withTypixMeta`, declaration merging)
- Common pitfalls (extension array stability, theme CSS import, `[0]` config bug)
- How to add new extensions, custom commands, and UI components
- File layout conventions (`components/typix/editor-ui/`)

The CLI generates this file by composing a curated Typix-knowledge section with details detected from your project (installed extensions, vendored components, framework).

---

## Options

| Flag | Description |
|---|---|
| `--path <file>` | Output path (default: `./AGENTS.md`) |
| `--merge` | If `AGENTS.md` already exists, merge the Typix section in instead of overwriting the file. Idempotent — re-running updates only the Typix section. |
| `--overwrite` | Replace any existing file at the path (default: refuses if the file exists) |
| `--print` | Print to stdout instead of writing to a file |
| `--no-cache` | Refetch the latest curated Typix-knowledge section from the registry |

```bash
typix agents-md

```

### Merge into an existing AGENTS.md (recommended for monorepos / existing projects)

```bash
typix agents-md --merge
```

The CLI looks for a `<!-- typix:start -->` / `<!-- typix:end -->` block. If found, it replaces just that section. Otherwise it appends one to the end of the file.

### Print without writing

```bash
typix agents-md --print
```

Useful for piping into other tools, or just inspecting before committing:

```bash
typix agents-md --print | less
```

## Authoring patterns

### Creating an editor

```tsx
const editor = useTypixEditor({
  extensions,    // MUST be defined at module scope or memoized — else editor recreates every render
  content: '<p>Hello</p>',
  onUpdate: ({ editor }) => save(editor.getJSON()),
})

if (!editor) return null

return (
  <TypixEditorContext.Provider value={{ editor }}>
    <Toolbar />
    <EditorContent editor={editor} />
  </TypixEditorContext.Provider>
)
```

### Adding a chain command

Extensions augment `TypixCommands<R>` themselves; the CLI's `add` command prints the snippet.
Inside design system code, NEVER do `(editor.chain() as any)[someStringVar]()` — use typed dispatchers.

### Defining a new extension

```tsx
import { defineExtension, FORMAT_TEXT_COMMAND } from "lexical"
import { withTypixMeta } from "@typix-editor/core"

export const MyExtension = withTypixMeta(
  defineExtension({ name: "my-ext", register: ... }),
  {
    commands: () => ({ toggleMine: () => (e) => e.dispatchCommand(...) }),
    shortcuts: [{ key: "m", modifiers: ["mod"], command: "toggleMine" }],
  },
)

declare module "@typix-editor/core" {
  interface TypixCommands<R> {
    toggleMine(): R
  }
}
```

## Common pitfalls

1. **`configExtension(Ext, {...})[0]` discards the config.** Use the tuple form: `configExtension(Ext, {...})` (no `[0]`).
2. **Extensions array must be stable.** Define at module scope or wrap in `useMemo`.
3. **Typix styles must be imported.** Add `@import "@typix-editor/ui/styles";` to your global CSS (after `@import "tailwindcss";`).
4. **`useTypixEditor` returns `null` on first render with `immediatelyRender: false`.** Always guard with `if (!editor) return null`.
5. **Decorator nodes (images, mentions, tables) require `ReactExtension`.** `useTypixEditor` handles this — don't try to bypass.

## File layout

- `app/page.tsx` — page renders the editor
- `components/typix/editor.tsx` — the `<Editor />` component
- `components/typix/editor-ui/` — vendored UI components (edit freely)
- `app/globals.css` — must import `@typix-editor/ui/styles`

<!-- typix:end -->
```

The curated section ("Authoring patterns", "Common pitfalls") comes from a versioned template inside the CLI. The "detected" sections are filled in from your project state.

---

## When to regenerate

Run `typix agents-md --merge` whenever:

- You install or remove extensions (so AI tools know the current set)
- You vendor new UI components
- You upgrade Typix core to a new major version (curated section may have new patterns)
